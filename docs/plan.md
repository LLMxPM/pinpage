# PinPage 首版项目规划

## 1. 项目定位与当前状态

PinPage 将网页固定在桌面其他普通窗口上方，主要服务于计时器、工作看板和本地工具页。

首版优先支持 Windows，围绕同时使用 1～5 个轻量页面设计，提供普通边框和无边框两种显示方式。

首个开发版本已落地 Tauri/Vue 脚手架和主要应用功能。此文档保留首版范围与验收目标，实际完成情况、性能数据和未覆盖场景见 [验证记录](verification.md)。

## 2. 使用场景

| 场景 | 典型输入 | 关键体验 |
| --- | --- | --- |
| 计时器 | 本地倒计时 HTML、在线番茄钟 | 长时间显示、时间准确、窗口较小 |
| 看板 | HTTP/HTTPS 页面、局域网服务 | 保留登录状态、持续更新、随时刷新 |
| 本地工具 | HTML 及配套 CSS、JS、图片 | 选择入口即可运行，资源路径可正常解析 |
| 前端开发预览 | 本地开发服务器 URL | 使用已有服务器，快速修改地址和调整尺寸 |

## 3. 首版功能范围

### 页面来源

- 支持 HTTP/HTTPS 地址，补全常见的无协议地址，并展示解析或加载错误。
- 支持选择本地 HTML 入口文件，默认以所在目录为资源根目录。
- 支持另选静态网站根目录，以覆盖入口位于子目录、需要引用其他目录资源的情况。
- 支持中文、空格和嵌套目录的文件路径，以及常见静态资源、JavaScript 模块和本地 JSON 请求。
- 本地需要后端执行能力或构建转换的项目，通过已有服务地址打开。

### 窗口与控制

- 创建多个独立悬浮窗，每个窗口可单独切换置顶和边框。
- 悬浮窗默认隐藏任务栏图标，管理窗口保留任务栏入口；通过托盘和快捷键管理悬浮窗。
- 支持移动、四边及四角缩放、最小化、显示、隐藏、刷新和关闭。
- 设置合理的最小尺寸，允许小型计时器窗口使用。
- 托盘提供管理界面入口、各窗口操作、恢复边框、显示全部和退出应用。
- 首版提供可配置的全局快捷键：默认 `Ctrl+Alt+P` 打开管理界面，`Ctrl+Alt+B` 找回全部窗口；单窗操作由工作台和托盘中的明确窗口入口触发。
- 关闭管理界面时销毁管理 WebView，应用和现有悬浮窗继续运行。
- 关闭悬浮窗默认销毁对应内容 WebView，并取消该窗口的自动恢复记录。
- 显式退出应用时保存仍打开的窗口，供下次按设置恢复。

### 状态与异常

- 保存页面来源、窗口位置、尺寸、置顶状态、边框状态和是否自动恢复。
- 保留应用自身的网页登录数据；不依赖系统浏览器已有登录状态。
- 启动时校验本地入口是否仍存在，对失效记录提供重新选择入口。
- 显示器布局或 DPI 变化后，校正恢复位置与尺寸，保证窗口可找回。
- 处理非法 URL、文件不存在、资源越界、导航失败和快捷键占用等错误。
- 新窗口请求默认交给系统浏览器；依赖应用内弹窗的登录流程作为兼容性测试项记录。

### 后续扩展

根据首版使用反馈再安排收藏、窗口预设、贴边吸附、透明度、鼠标穿透、自动刷新、文件变化监听和跨平台适配。

## 4. 技术架构

| 模块 | 技术或方式 | 职责 |
| --- | --- | --- |
| 管理界面 | Vue 3、TypeScript、Vite | 页面入口、悬浮窗列表、设置和错误反馈 |
| 应用核心 | Tauri 2、Rust | 命令入口、状态管理、窗口注册表和系统集成 |
| 内容窗口 | 每窗一个原生 WebView | 渲染远程页面或本地 HTML |
| 本地资源 | 受控自定义协议 | 将 URL 映射到授权目录内的静态文件 |
| 配置 | 带 schemaVersion 的 JSON | 应用设置、窗口状态和后续数据迁移 |
| Windows 适配 | 独立平台模块 | 无边框命中、拖动缩放等必要的原生补充 |

管理界面调用 Rust 层创建和控制内容窗口，目标网页不参与应用管理操作。窗口数据以 Rust 层为准，管理界面重新创建后读取现有窗口与配置。

窗口和 WebView 创建使用异步命令等官方支持的调用方式，规避 Windows 上同步命令或事件回调中创建窗口的已知阻塞问题。

### 主要架构决策

1. **控制界面与内容分离**：首版通过管理界面、托盘和快捷键控制窗口。
2. **共享浏览器基础设施**：默认统一 WebView2 环境配置和数据目录，避免无必要的环境隔离。
3. **按需创建管理界面**：不为控制界面保留长期隐藏的 WebView。
4. **先验证无边框交互**：原生边缘缩放不满足要求时，在 Windows 适配层补充命中处理；恢复边框始终可用。
5. **窗内工具栏独立评估**：同窗多 WebView 在 Tauri 2 中需要 unstable 特性，完成技术验证后再决定是否采用。
6. **首版采用 JSON 配置**：通过版本号、默认值和原子替换写入支持演进，窗口变化防抖保存。

当前实现中，无边框模式关闭 Windows 原生阴影以启用完整边缘命中；Alt + 左键移动由独立 Windows 适配模块处理，普通模式仍使用系统标题栏。

## 5. 本地内容加载与权限边界

为每个本地内容来源建立独立的资源映射和来源标识，避免不同工具页意外共享同源存储。相同来源恢复时保持标识稳定。

本地协议处理流程：

1. 根据请求所属 WebView 和来源标识找到已授权资源根目录。
2. 解析资源 URL，处理百分号编码、中文、空格及相对路径。
3. 解析并规范化真实文件路径，检查目录联接、符号链接及目录穿越。
4. 确认最终路径仍位于授权根目录内，按正确的 MIME 类型返回资源。
5. 对缺失或越界资源返回明确错误，不回退读取其他目录。

管理界面的权限只匹配受信任的 WebView 标签；远程网页和用户本地 HTML 均不授予应用管理、Shell 或通用文件系统权限。自定义命令需要独立校验调用方，资源协议需要独立校验访问范围。

远程内容导航时校验协议类型；外部链接处理与管理界面导航分开，防止管理 WebView 被替换为任意网页。

## 6. 数据模型

| 模型 | 主要字段 |
| --- | --- |
| AppSettings | schemaVersion、是否恢复会话、控制快捷键、窗口配置列表 |
| PinConfig | id、名称、source、窗口尺寸与位置、显示器与缩放信息、置顶、边框、自动恢复 |
| PageSource | URL 来源，或本地入口、资源根目录与稳定来源标识 |
| PinRuntime | 原生窗口标签、加载状态、当前地址与标题、可见状态、最近错误 |

持久化配置与运行态分离。配置不保存密码、网页 DOM、完整 JS 内存状态或浏览器 Cookie；网页存储由 WebView2 自身管理。刷新、销毁和重启可能丢失页面尚未保存的运行状态。

## 7. 性能与计时要求

多窗口不等于每个窗口都需要独立的完整浏览器进程组，但每个网页仍有运行开销。实际渲染进程数量由引擎、站点隔离和页面内容共同决定。

- 各窗口采用兼容的 WebView2 环境选项和共享数据目录，具体共享结果通过原型观察确认。
- 每个悬浮窗仅创建一个内容 WebView，管理 WebView 按需创建并销毁。
- 可见计时器和看板持续运行；首版不默认挂起这些页面。
- 隐藏窗口不等于释放内存。后续若增加自动销毁或挂起，必须明确恢复与页面状态丢失的行为。
- 自带计时样例按目标截止时间计算剩余时间，避免使用回调次数累计秒数；覆盖后台节流、休眠与恢复。
- 对第三方计时页面验证实际行为，应用不承诺修正第三方页面自身的计时实现。

### 性能测量矩阵

| 页面组合 | 窗口数 | 测量项目 |
| --- | --- | --- |
| 最小静态页面基线 | 1 | 浏览器基础开销与单页面增量 |
| 本地计时器 | 1、3、5 | 稳定内存、空闲 CPU、计时准确性 |
| 计时器 + 看板 + 本地工具混合 | 3、5 | 实际使用成本、持续运行趋势 |
| 管理界面开关、内容窗口创建关闭 | 多次重复 | 关闭后的资源变化与异常增长 |

使用 Release 构建，记录系统、硬件、WebView2 版本、页面样例和测量时长。收集主程序与相关 WebView2 进程的私有内存、工作集、CPU 和进程数，说明共享内存统计口径，避免直接累加工作集造成误判。首轮数据形成后再制定数值预算。

## 8. 建议目录

```text
src/
  features/
    launcher/             地址输入与文件选择
    pins/                 悬浮窗列表和设置
  components/             通用组件
  services/               Tauri 调用封装
  types/                  前端类型
src-tauri/src/
  commands/               前端命令入口
  windows/                窗口生命周期和注册表
  content/                URL 与本地资源处理
  platform/windows/       Windows 专用适配
  persistence/            配置读写与迁移
  tray.rs                 托盘入口
  lib.rs                  应用装配
docs/
  plan.md                 首版规划
```

根据实际代码复杂度创建模块，避免为了占位提前生成大量空文件。

## 9. 实施阶段与验收

### P0：脚手架与技术验证

- 创建 Tauri 2、Vue 3、TypeScript 和 Vite 项目，使用 pnpm。
- 建立最小管理入口与多个内容窗口，验证共享环境配置。
- 验证远程页面、本地 HTML、样式、图片、JS 模块和 JSON 请求。
- 验证置顶、切换边框、无边框拖动及四边四角缩放。
- 验证托盘恢复操作、100%/150%/200% 缩放和至少两种显示器布局。
- 完成首轮 1、3、5 个窗口的资源测量，并记录结果与待解决问题。

验收：核心窗口交互和本地资源加载有实际运行证据；若发现框架限制，先修正规划，再进入可用版本开发。

### P1：首个可用版本

- 完成地址输入、文件选择、窗口列表和单窗设置。
- 完成托盘控制、快捷键和清晰的生命周期行为。
- 实现配置保存、会话恢复、文件失效提示和窗口位置校正。
- 完成权限隔离、导航处理、加载错误与异常恢复提示。

验收：可以完成“打开 3 个页面 → 调整位置大小 → 切换无边框 → 关闭管理界面 → 托盘找回 → 退出并重启恢复”的完整流程。

### P2：首版交付

- 使用计时器、看板和本地工具页各至少一个样例进行持续运行验证。
- 验证断网重连、睡眠恢复、显示器变化和登录相关兼容性。
- 验证恶意路径、越界资源请求及非管理 WebView 调用命令被拒绝。
- 复测 Release 性能并说明已知限制，生成 Windows 安装包并验证安装启动。
- 更新 README，补齐实际开发、构建、使用步骤和兼容性说明。

验收：目标机器可以安装并运行，主流程完成，性能结果和限制可复查；存在未解决问题时明确标记，不提前宣布验收通过。

## 10. 待原型确认的事项

- 当前 Tauri/WebView2 版本下，无边框窗口的原生拖动缩放表现及所需适配。
- 自定义协议对 JS 模块、fetch、存储和来源隔离的实际兼容性。
- 管理窗口关闭重建与共享环境的真实资源变化。
- 代表性看板的登录跳转、弹窗、刷新和长期运行行为。
- 普通桌面窗口上方置顶作为首版目标；独占全屏、系统安全桌面等场景单独记录兼容性。
