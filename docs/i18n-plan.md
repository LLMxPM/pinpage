# PinPage 多语言实施规划

状态：M1 → M3 已实施并通过自动检查，M4 的安装包已按中英文构建，桌面与安装验收尚未完成。编写日期：2026-11-06，实施日期：2026-11-06。

本规划以现有 Tauri 2 / Vue 3 应用为基础，补充[首版项目规划](plan.md)。首批提供简体中文和英文，覆盖工作台与应用原生入口；默认界面保持中文。完成情况统一记录到[验证记录](verification.md)，下文的目标行为不代表已验收能力。

实施过程中的三处契约收敛，与本规划原文略有出入，以本节为准：

- 消息码直接采用 native 资源键（如 `errors.invalidUrl`），不再额外维护业务码到翻译键的映射表；Rust 与前端读取同一份 `native.json`，少一处可能漂移的对照表。
- 中英文键完整性、参数一致性和 native 资源语法约束全部由 `pnpm check:i18n` 承担，未引入 Vue I18n 的 TypeScript 资源类型增强：渲染 Rust 消息时键来自运行时，严格类型只能靠断言绕过，反而掩盖问题。
- 旧字符串错误通道在本次一次性迁移中直接删除，没有保留「第一批兼容旧字符串」的过渡层。

## 1. 当前基础与改造范围

当前没有国际化依赖或语言设置。需要处理的文案跨越前端与 Rust，不能只替换 Vue 模板。

| 现有位置                                                            | 当前情况                                       | 计划改动                                                   |
| ------------------------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------- |
| `src/App.vue`、`src/features/`、`src/components/SettingsDialog.vue` | 按钮、状态、说明、弹窗及无障碍标签写死为中文   | 提取翻译键，包含 `title`、`aria-label`、占位文字和完整句子 |
| `src/features/pins/useWorkspace.ts`                                 | 错误直接转字符串；导出结果拼接中文             | 按消息结构渲染，成功提示支持参数和复数                     |
| `src/services/format.ts`                                            | 字节体积使用固定数字格式                       | 显示格式使用当前语言，原始数据与单位口径保持稳定           |
| `src-tauri/src/models.rs`、`state.rs`、`commands.rs`                | 设置没有语言字段；错误、通知为字符串           | 新增语言契约、兼容读取和结构化消息                         |
| `src-tauri/src/tray.rs`、`windows/mod.rs`                           | 托盘、提示文字和管理窗口标题为中文             | 由 Rust 根据同一有效语言渲染                               |

首批包含应用拥有的工作台、设置、托盘、错误与通知、文件选择器自定义标题及过滤器名称、恢复引导页和安装界面。文件选择器中的系统按钮由 Windows 决定，可能与应用语言不同。

远程网页、用户导入 HTML、网页标题、用户命名、文件路径、URL、页面包内的数据均保留原值。内置计时器的导入名称按当前应用语言生成，其 HTML 内容作为独立工具页，内容双语化列入后续扩展；已有副本不自动改写。项目协作文档继续使用中文。

## 2. 语言与切换规则

### 2.1 首批语言

| 设置值   | 选项名称          | 含义                                           |
| -------- | ----------------- | ---------------------------------------------- |
| `zh-CN`  | 简体中文          | 新安装及旧配置升级后的默认值，也是最终回退语言 |
| `en-US`  | English           | 首批英文资源；其他英语地区暂共用此资源与格式   |
| `system` | 跟随系统 / System | 由 Rust 解析 Windows 用户首选界面语言          |

语言选项中的“简体中文”和“English”固定使用自称，避免切换后找不到恢复入口。`system` 是用户偏好，不是翻译资源名称。

解析顺序如下：

1. 明确选择中文或英文时，直接使用对应资源。
2. 选择 `system` 时，按 Windows 用户首选界面语言的顺序，寻找第一个可匹配的语言：`en` 及其地区变体匹配 `en-US`，`zh` 及其变体匹配 `zh-CN`。首批不提供繁体资源，界面需说明中文统一为简体。
3. 没有可匹配语言、列表为空或系统读取失败时，回退到 `zh-CN`。例如 `de-DE, en-GB` 选择英文，只有 `de-DE` 时选择中文。

Windows 读取使用平台适配模块封装的 `GetUserPreferredUILanguages`，返回有序语言列表，避免由 WebView 的浏览器语言决定托盘语言。[Windows 官方接口说明](https://learn.microsoft.com/en-us/windows/win32/api/winnls/nf-winnls-getuserpreferreduilanguages)

系统偏好在应用启动和用户保存 `system` 时重新解析。首批不监听运行期间的系统语言变化；更改 Windows 语言后重启应用即可生效。非 Windows 构建暂回退中文，不因此新增跨平台承诺。

### 2.2 保存与运行行为

- 在“工作台设置”增加语言选择，和现有设置一起保存；取消关闭不改变当前语言。
- 保存成功后，当前工作台、管理窗口标题、托盘菜单与提示同步更新，无需重启应用。
- 关闭再打开管理界面时，从 Rust 快照恢复有效语言。使用 `--tray` 启动时，托盘也能独立得到正确语言。
- 切换语言只更新应用界面，不刷新、销毁或重建内容 WebView，不改变页面计时、登录态或窗口几何设置。
- 已打开的系统文件选择器、一次性数据恢复引导页保持打开时的语言，下一次创建使用新语言。
- 已保存的页面名称保持原值，包括此前自动生成的名称；新建时的兜底名称与示例名称才使用当前语言。

## 3. 实现方案

### 3.1 前端国际化与资源组织

采用 Vue I18n 的 Composition API，通过 `createI18n({ legacy: false })` 和 `useI18n()` 接入现有 Vue 3 组件；中文资源提供类型结构，英文键完整性另由脚本校验。[Composition API](https://vue-i18n.intlify.dev/guide/advanced/composition)、[TypeScript 资源类型](https://vue-i18n.intlify.dev/guide/advanced/typescript)

首批资源随应用打包，不联网下载。使用 `@intlify/unplugin-vue-i18n` 预编译资源，保留现有管理界面 CSP；先验证所选版本与项目 Vite / TypeScript 的兼容性，并用 pnpm 锁定依赖。Release 中验证翻译渲染，不通过增加 `unsafe-eval` 解决兼容问题。[Vue I18n 构建与 CSP 说明](https://vue-i18n.intlify.dev/guide/advanced/optimization)

建议目录按职责建立，实际实施时创建文件：

```text
locales/
  zh-CN/
    ui.json                 工作台文案，可使用 Vue I18n 复数语法
    native.json             托盘、原生标题和共用错误，仅普通文字与命名参数
  en-US/
    ui.json
    native.json
src/
  i18n/
    index.ts                Vue I18n 装配、资源合并和语言应用
    messages.ts             消息码到翻译键的映射与未知错误回退
  types/
    messages.ts             结构化消息契约
src-tauri/src/
  i18n.rs                   嵌入原生资源、翻译与回退
  errors.rs                 稳定消息码、参数和错误转换
  platform/locale.rs        Windows 首选界面语言读取
scripts/
  check-i18n.mjs            资源键、参数、语法与原生资源约束检查
```

前端加载两类资源，分别放入 `ui` 与 `native` 命名空间。Rust 通过 `include_str!` 嵌入同一份 `native.json`，不另存一套翻译。Rust 只实现点分键查找和 `{name}` 参数替换；原生资源禁止复数表达式、链接、HTML 及 Vue 专用语法，由检查脚本约束，避免维护两套消息解析器。

键使用稳定的业务含义，如 `ui.settings.language`、`native.tray.openManager`，不用中文原文或组件行号作键。完整句子作为翻译单元，避免先翻译“已导出”、再拼文件数。前端英文计数覆盖 0 / 1 / 多个；原生计数提示采用不依赖单复数变化的表达。

资源不含用户数据；参数以文本插值渲染。禁止将翻译结果交给 `v-html`，恢复引导页插值必须正确转义，不能因多语言放宽 CSP 或内容 WebView 权限。

### 3.2 配置与 IPC 契约

| 模型                        | 新增或调整                               | 约束                                          |
| --------------------------- | ---------------------------------------- | --------------------------------------------- |
| `Settings`、`SettingsInput` | `locale: 'zh-CN' \| 'en-US' \| 'system'` | 只持久化用户偏好，Rust 是唯一配置来源         |
| `Snapshot`                  | `resolvedLocale: 'zh-CN' \| 'en-US'`     | 启动时 Rust 已解析，前端不再自行猜测系统语言  |
| `PinRuntime.error`          | `AppMessage \| null`                     | 保存消息码及参数，不保存已翻译句子            |
| `Snapshot.notices`          | `AppMessage[]`                           | 历史通知可按当前语言重新渲染                  |
| 管理命令错误                | 可序列化 `AppMessage`                    | 由集中 IPC 封装处理，业务组件不匹配错误字符串 |

兼容策略：

- 保持 `schemaVersion: 1`。新增字段是兼容扩展；当前 `AppState::load` 仅接受版本 1，直接升号会将原配置当作异常备份并重置。
- 配置缺少 `locale` 时默认中文。持久化读取对未知值、非字符串值容错，仅将该字段回退中文，保留页面、快捷键和其他设置；不让未知语言枚举导致整份配置解析失败。
- IPC 输入严格校验，只允许三个约定值；非法输入返回明确错误，不能按配置读取的容错规则静默接受。
- 继续使用现有原子写入。更新时串行校验语言、快捷键及候选设置，持久化失败须回滚本次快捷键变更，内存与当前语言保持原值；保存成功后再发布新语言与快照。
- 结合现有 `AppState.operation` 与配置写入锁安排更新，防止保存语言时覆盖并发窗口状态。原生 UI 更新前释放状态锁，避免菜单重建与状态读取互相等待。
- 延用仅发往 `main` 的 `pins-changed` 通知；快照携带完整语言状态，无需向内容页广播应用配置。

### 3.3 启动与切换流程

1. Rust 读取兼容配置并计算有效语言，在创建托盘、管理窗口及恢复引导页前准备好原生翻译。
2. 管理前端先订阅状态变化，再取得初始快照，应用 `resolvedLocale` 后呈现业务界面；等待期间使用无文字加载壳，减少英文用户看到中文闪烁。浏览器预览默认中文，不伪装为已连接的桌面应用。
3. 前端应用语言时同时更新 Vue I18n、`document.documentElement.lang` 和 `document.title`。Rust 更新管理窗口系统标题，管理窗口重建时也从有效语言取标题。
4. 用户保存设置后，由 Rust 持久化并更新有效语言，重建托盘菜单、更新 tooltip 和窗口标题，通知管理界面重取快照。
5. 托盘刷新失败时保留原有可操作菜单，记录结构化通知并提供重试路径；配置已经保存时，反馈“设置已保存，托盘更新失败”，避免误报为整次保存失败。双语验收必须观察到实际菜单更新成功。

`useWorkspace.ts` 的成功提示也保留消息键和参数，不能提前固化为中文字符串；切换时仍可见的提示、卡片错误与通知随语言更新。翻译调用放在模板或 `computed` 中，避免初始化时生成的常量不响应语言变化。

### 3.4 结构化错误与通知

统一消息结构为 `{ code, args, detail? }`：`code` 是稳定业务码，例如 `INVALID_URL`；`args` 是受控的字符串或数字参数；`detail` 保留第三方或系统错误的诊断文字。集中映射业务码到 `native.errors.*`，同一错误在 Rust 原生入口和前端使用同一资源。

- 自有校验、窗口操作、导入导出、配置读写和快捷键错误逐条改为业务码；禁止按中文子串判断错误类型。
- 对系统及第三方错误使用当前语言的说明，原始诊断文字放入详情，允许详情保留系统语言。未知 IPC 拒绝值也经过统一回退，避免出现 `[object Object]`。
- `state.rs` 的启动通知与运行通知存储消息结构。通知去重按消息码和参数判断，保留现有数量上限。
- `content.rs` 的资源协议错误需要区分返回对象：受信任管理界面可看诊断详情；不受信任内容只收到必要状态及安全摘要，不增加本地路径或配置泄露。
- 内容页数据回传仍使用原有身份、体积与导出会话校验。多语言改造不授予内容页语言设置或管理 IPC。
- 第一批迁移时在 IPC 边界兼容旧字符串错误；完成原生迁移后清理自有字符串通道，第三方未知错误的回退仍保留。

### 3.5 显示格式与布局

数量和展示用小数使用当前语言的 `Intl.NumberFormat`；字节体积继续按 1024 换算，保留 B / KiB / MiB / GiB。数字格式只影响展示，不改动尺寸、坐标、JSON 或 IPC 数值。现有窗口尺寸输入先保留原生数值语义，不自行实现地区化数字解析。

英文长文案需要检查侧边栏、创建按钮、卡片徽标、快捷键说明和弹层。允许换行并给文字合理空间；关键操作不能仅靠省略号区分。至少覆盖管理窗口最小尺寸 760 × 620、100% / 150% / 200% DPI、键盘导航和屏幕阅读器标签。首批只支持从左向右排版，RTL 另行设计。

### 3.6 安装包

NSIS 在 `bundle.windows.nsis` 中配置 `languages: ["SimpChinese", "English"]` 和 `displayLanguageSelector: true`，保持单个安装包。安装器语言与应用的 `settings.locale` 独立，安装器选择英文不会隐式修改现有用户设置；安装与卸载流程均需实测。[Tauri NSIS 多语言配置](https://v2.tauri.app/distribute/windows-installer/#internationalization-1)

## 5. 验证矩阵与执行约束

| 层次     | 必测场景                                                     | 通过标准                                                            |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------------------- |
| 配置兼容 | 缺字段、未知语言、非字符串语言、已有页面及快捷键             | 仅语言回退，其他字段及 enabled 状态不变，不触发整份备份重置         |
| 偏好解析 | 显式中英文、英语地区变体、中英文系统列表、无匹配、读取失败   | 符合第 2 节顺序，显式选择不被系统覆盖                               |
| 保存异常 | 非法 IPC 值、快捷键冲突、配置写入失败、托盘刷新失败          | 原设置能保留或回滚，已保存与原生显示失败能被区分，无并发覆盖        |
| 翻译资源 | 缺键、多键、空翻译、参数集合不一致、非法原生语法             | `check:i18n` 失败并定位资源；运行时缺键回退中文，未知消息有可读兜底 |
| 文案格式 | 0 / 1 / 多文件、字节边界、中文路径、含括号与花括号的名称     | 语法、数字和参数正确，用户数据作为文字保留，不能变成消息模板        |
| 界面布局 | 两种语言、最小窗口、100% / 150% / 200% DPI、键盘操作         | 操作可见可达，标签与提示语言一致，无关键文字截断                    |
| 生命周期 | 中文 → 英文 → 中文、取消设置、管理页销毁重建、重启、`--tray` | 偏好与有效语言一致，托盘和管理页无需互相依赖才能显示正确语言        |
| 页面状态 | 运行中的计时器、已登录页面、关闭的页面、导入页数据           | 切换不重载内容页，不改名，不修改页面数据与 enabled 状态             |
| 安全回归 | 非管理 WebView 更新设置、越界资源、注入形态的消息参数        | 既有权限拒绝仍成立，无 HTML 执行或新增路径泄露，CSP 无放宽          |
| Release  | 中英文安装 / 卸载、托盘操作、原生标题和选择器、恢复引导页    | 实际显示正确，预编译翻译在生产 CSP 下运行，系统文案边界有记录       |

实施期间为配置容错、语言解析、资源约束和消息转换补充聚焦测试；优先使用现有 Rust 测试及轻量 Node 检查，不为多语言引入整套新的前端测试框架。执行相关的 `pnpm check:i18n`、`pnpm build`、`pnpm format:check`、Rust 测试和格式检查；M4 再做 Release 打包与桌面验证。文案静态扫描只作审查辅助，不能把中文注释和诊断日志一律判为漏翻。

复用已运行的开发服务，桌面验证使用独立应用标识或测试配置，不覆盖用户会话。多语言不新增常驻 WebView；首批资源均本地打包，不引入网络翻译。只有出现新的性能疑点时才追加针对性测量，不把本次文档或功能改造写成性能收益。

## 6. 后续扩展与维护

- 新增语言时，补齐两类资源、语言注册与系统匹配规则，并运行键和参数检查、布局验收；不能只增加一个 JSON 文件就标记支持。
- 内置计时器内容可另做独立双语版本，语言偏好属于工具页自身；与应用同步需要单独设计，不能给用户 HTML 开放管理权限，也不自动覆盖已导入副本。
- 根据真实使用反馈再安排繁体中文、其他语言、RTL、自动感知系统语言变化、在线翻译协作及英文项目文档。
- 新增可见文案时同步提交中英文资源；共用错误维护业务码，路径、URL、用户内容和第三方诊断不进入翻译目录。
