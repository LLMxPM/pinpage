## 导入式本地网页

### 实现行为

- 本地来源改为导入：`import_page` 通过原生选择器扫描目录或单文件，返回入口候选、文件数与体积预览，用户确认后才复制文件。
- 目录导入以所选目录为站点根，入口只取根目录下的 HTML；多个候选时由用户选择。单文件导入只复制入口本身。
- 副本写入 `%APPDATA%\com.pinpage.desktop\pages\{页面 ID}\site`，`PageSource::Bundled` 只记录相对入口，加载不再访问原始目录。
- 复制跳过符号链接与目录联接，单次上限 4000 个文件或 256 MiB；统计和复制阶段各校验一次，避免统计后文件继续变大。
- 创建时校验入口属于扫描候选、位于所选目录内且为 HTML；页面 ID 必须是单级目录名，防止配置被改写后越出 pages 根目录。
- 删除页面记录时清理对应站点副本；旧版 `Local` 来源保留解析逻辑，仅用于兼容已有配置。

## 页面包导出与示例导入

### 实现行为

- 导出把站点副本、`manifest.json` 与 localStorage/sessionStorage/IndexedDB 快照写成 `.pinpage`（ZIP）。
- 采集通过注入脚本完成，数据由 `submit_page_data` 回传；该命令只在导出会话期间、且只接受同 ID 页面发起的调用。
- IndexedDB 逐个数据库读取：记录数据库版本、store 的 keyPath 与自增设置、索引定义和全部记录；单库超过 3000 条后截断并标记。
- 记录值按类型编码，覆盖 Date、ArrayBuffer、TypedArray、Blob、BigInt、RegExp 与 NaN/Infinity；Map/Set 等结构化类型标记为不支持。
- 导出要求页面处于运行状态；未运行直接拒绝，数据读取超时则只打包站点副本并在结果中标注。
- 导入页面包解压到站点副本，拒绝绝对路径与上级目录条目，入口必须是包内 HTML。
- 随包数据写入 `pending-data.json`；页面首次打开时先加载应用内引导页，在同源空白页完成 localStorage 与 IndexedDB 回填，再 `location.replace` 到入口，避开与页面脚本争抢建库时序。
- 引导页数据由固定路径 `data.json` 提供，读取一次即删除，重复加载会直接跳转入口。
- 内置示例改为导入式：`examples.rs` 把编译进二进制的示例写成站点副本，与用户导入页同构，不再有独立的只读示例加载分支。
- 示例同时使用两条数据路径：计时状态存 localStorage，完成的轮次写入 IndexedDB 的 `sessions` 表（自增主键与 `finishedAt` 索引），作为导出导入的实际用例。

## 多语言（简体中文 / 英文）

按 [多语言实施规划](i18n-plan.md) 落地 M1 → M3，并生成 M4 的中英文安装包。界面语言偏好为 `zh-CN` / `en-US` / `system`，默认简体中文。

### 实现行为

- 语言偏好持久化在 `settings.locale`，Rust 在创建托盘和管理窗口之前解析出有效语言，快照以 `resolvedLocale` 返回；前端不再自行猜测系统语言。
- `system` 通过 `GetUserPreferredUILanguages` 读取 Windows 用户首选界面语言，按列表顺序取第一个可匹配语言（`en*` → 英文，`zh*` → 简体），无匹配或读取失败回退中文。非 Windows 构建回退中文。
- 旧配置缺少 `locale`、语言取值未知或不是字符串时，只把该字段回退中文，页面记录、快捷键和 `enabled` 状态保持不变，不触发整份配置备份重置。IPC 输入则严格校验，非法语言直接返回「语言设置无效」。
- 保存设置时按「校验语言 → 注册快捷键 → 写入配置 → 持久化」顺序进行，持久化失败回滚本次全部改动（含快捷键）；成功之后才发布新语言并重建托盘菜单、更新 tooltip 和管理窗口标题。托盘刷新失败单独提示「设置已保存，但托盘菜单更新失败」，不谎报整次保存失败。
- 错误与通知改为 `{ code, args, detail }` 结构：`code` 直接是 native 资源键，Rust 与前端读取同一份 `locales/{语言}/native.json`，切换语言后可见通知和卡片错误重新渲染，不保存已翻译句子。系统及第三方错误的原文放在 `detail`，允许保留系统语言。
- 资源协议向不受信任的内容页只返回当前语言的简短说明和 `X-PinPage-Error` 消息码，不再回显本地路径；诊断细节写入日志。管理界面的 CSP 与内容 WebView 权限未放宽。
- 翻译资源在构建期预编译，产物不含消息编译器；`pnpm check:i18n` 负责中英键一致、参数一致、native 资源禁复数/链接/标记语言，以及代码中消息键是否落库。
- 语言切换只更新 Vue I18n、`document.documentElement.lang` 和文档标题，不刷新、销毁或重建内容 WebView；已保存的页面名称、页面数据和 `enabled` 状态不受影响。语言下拉中的「简体中文」和「English」固定使用自称。
- 内置计时器仍作为独立工具页，其 HTML 内容保持原有中文；导入后生成的名称按当前应用语言取「专注计时器 / Focus Timer」，已有副本不自动改写。

## 性能采样

采样命令如下，先在界面中确认实际打开的悬浮页数量：

```powershell
./scripts/measure-memory.ps1 -WindowCount 1 -Label timer-idle
./scripts/measure-memory.ps1 -WindowCount 3 -Label timer-idle
./scripts/measure-memory.ps1 -WindowCount 5 -Label timer-idle
```

原始结果写入已忽略的 `runtime-data/memory-samples.jsonl`，不收集页面地址或网页内容。

私有字节表示进程私有提交内存，不能等同于物理驻留内存。工作集求和包含共享页，不能直接作为实际物理内存总量。CPU 百分比按单个逻辑核心计，短时样本仅用于首轮观察。

### 首轮 Release 数据

测试日期：2026-11-06。环境：Windows 10.0.26300.0、WebView2 156.0.4314.58、16 个逻辑处理器。页面为默认 420 × 360 的内置计时器，处于未开始计时状态，使用 `--tray` 启动，管理界面未创建。

每组独立启动，等待约 10 秒后采样 5 秒。后半段桌面自动化返回 `GetCursorPos failed: 拒绝访问 (0x80070005)`，资源采样通过进程指标完成，未继续依赖桌面输入；这组数据不能替代正常交互和持续计时负载测试。

| 悬浮页数量 | 整组私有提交内存 | 整组进程数 | CPU / 单逻辑核心 |
| --- | --- | --- | --- |
| 1 | 205.49 MiB | 7 | 4.06% |
| 3 | 291.34 MiB | 9 | 4.06% |
| 5 | 376.94 MiB | 11 | 5.00% |

5 个页面场景中观察到 1 个应用进程、1 个 WebView2 浏览器主进程、5 个渲染进程和 1 个 GPU 进程，其余为辅助进程。增加页面会增加渲染和页面运行开销，共享浏览器基础设施不会消除这些开销。

这些数值是私有提交内存，不能作为物理驻留内存结论。CPU 以一个逻辑核心为 100%，不是整台机器百分比。样本仅为首轮基线，暂不设置硬性内存上限。

计时样例已避免在显示内容没有变化时反复修改 DOM；正式性能数据应使用优化后的版本重新采样，避免混入早期开发样本。
