# 架构与数据

本文说明 PinPage 的模块划分、窗口模型、安全边界、本地数据与性能取舍。功能使用说明见[用户指南](user-guide.md)，构建与检查命令见[开发与构建](development.md)，平台差异与回退边界见[平台支持](platforms.md)。

## 技术组成

| 模块 | 技术或方式 | 职责 |
| --- | --- | --- |
| 工作台 | Vue 3、TypeScript、Vite | 页面入口、悬浮窗列表、设置与错误反馈 |
| 应用核心 | Tauri 2、Rust | 命令入口、状态管理、窗口注册表与托盘 |
| 内容窗口 | 每个页面一个原生 WebView | 渲染远程网页或本地 HTML |
| 本地资源 | 受控自定义协议 | 把 URL 映射到授权目录内的静态文件 |
| 配置 | 带 `schemaVersion` 的 JSON | 应用设置、窗口状态与后续数据迁移 |
| 平台能力 | 条件编译与快照能力表 | 声明可用能力、裁剪前端入口、校验原生提交并回退旧配置 |
| Windows 适配 | 独立平台模块 | 无边框命中、圆角裁剪、桌面挂载、几何锁与 DPI 校正 |

工作台通过 Rust 命令创建和控制内容窗口，目标网页不参与应用管理操作。窗口数据以 Rust 层为准；工作台重新创建后读取现有窗口与配置。窗口和 WebView 均通过异步命令创建，避免在 Windows 的同步命令或事件回调中阻塞。

## 窗口生命周期

- **工作台按需创建**：关闭即销毁其 WebView，不为控制界面保留长期隐藏的 WebView；悬浮页继续运行。工作台默认 1080 × 800，最小 760 × 620。
- **每个悬浮页一个内容 WebView**：创建时隐藏任务栏图标，保留工作台的任务栏入口；可通过托盘或卡片上的“带到最前”找回。
- **关闭与删除分离**：关闭页面释放 WebView 并把 `enabled` 置为 `false`，保留来源与窗口配置；删除才移除记录并清理导入副本。重启只恢复 `enabled` 为 `true` 的页面。
- **隐藏不等于销毁**：隐藏保留页面运行状态；关闭工作台、隐藏窗口和关闭页面是三种不同的生命周期状态。
- **位置与尺寸**：配置保存逻辑尺寸与物理坐标，并记录窗口缩放比例；恢复时按当前显示器可用区域校正，DPI 或显示器变化后窗口仍可找回。
- **视觉与交互**：无边框模式关闭原生阴影以启用完整边缘命中，可选圆角通过原生窗口区域裁剪实现；修饰键配合左键拖动或右键菜单、桌面挂载与几何锁由 Windows 适配模块处理。位置锁和大小锁独立生效，管理界面的明确设置提交会更新锁定锚点，常规拖动和系统布局请求不会绕过锁定。
- **平台能力**：Rust 按构建声明桌面模式、圆角、位置锁、大小锁和手势能力，快照下发同一份能力表；前端只按表裁剪入口，原生层在创建、应用、预设写入和恢复时终检。
- **跨平台回退**：加载其他平台写下的页面时，不支持的桌面模式、圆角与两把锁自动降级，桌面页转为带系统边框的浮动窗口，保留名称、来源、尺寸、位置和开关，并清除失效预设标记。显式 IPC 提交不支持的能力返回错误，不做静默写入。预设菜单只展示能完整应用的模板，管理器保留跨平台旧模板。具体矩阵与 macOS 限制见[平台支持](platforms.md)。
- **桌面模式**：页面挂载到 Explorer 的桌面图标宿主，使用无边框外观，位于普通应用窗口下方；切回浮动模式沿用此前选择的边框和置顶偏好。找回操作会切回浮动、恢复边框、解除位置锁并居中，大小锁保留。
- **窗口预设**：内置预设与自定义预设共用一组“外观 + 尺寸 + 归一化位置”字段。位置按目标显示器可用区域的比例保存，应用时换算成物理坐标；全屏项按目标显示器整屏动态换算逻辑尺寸并覆盖任务栏区域，再与外观一起交给同一套原生应用与回滚流程。名称、来源和开关状态不受影响。`preset` 表示当前匹配的模板；原生拖动、缩放和单字段切换偏离组合时清空，内容修改不影响它。窗口提交后按有效外观与目标显示器几何重新匹配，允许系统像素取整。模板修改只更新模板数据并清除失效标记，不重新应用现有窗口。
- **设置提交**：前端桌面任务按用户操作顺序排队。`update_window` 只接收窗口局部字段，在 Rust 操作锁内合并最新状态并返回事务前后快照；撤销附带期望字段，由原生层拒绝过期操作。`update_content` 只提交名称与可选来源，不重新应用几何。窗口即时设置、内容和预设编辑在明确落盘成功后才反馈成功，失败保留输入。


## 窗口鼠标手势

- 左键拖动与右键原生菜单共用 `gestureModifier`，支持 `alt`、`ctrl`、`shift`、`disabled`，默认仅左 Alt。修饰键须先于鼠标按下且精确匹配；右 Alt／AltGr、额外修饰键、已有捕获或系统菜单不接管。
- 唯一的 `WH_MOUSE_LL` 钩子运行在专属消息线程，仅在物理按下时匹配内容窗口白名单与实际客户区命中。匹配按钮成对消费，额外按钮或滚轮取消动作并排空已归属的按钮；普通操作、模拟输入和鼠标移动沿系统链放行，不轮询按键、不安装键盘钩子。
- 私有消息窗口把请求交给 UI 线程；窗口实例编号和手势票据共同淘汰迟到请求。宿主窗口负责鼠标捕获与 `SetWindowPos` 移动，不向 WebView 补发鼠标消息。系统拖动阈值仅在起步时生效，既有几何锁继续约束位置；这不是系统标题栏移动循环，不提供其边缘吸附行为。
- 手势期间暂时保留宿主键盘焦点，延后 Wry 的 WebView 焦点转交，使 Esc 能取消并恢复拖动起点；收尾后恢复正常焦点消息链，不抢回其他窗口已获得的焦点。捕获丢失、取消、设置改变或窗口销毁会结束当前捕获。
- 按住 Alt 的键盘自动重复会发送 `VK_MENU` 系统按键消息，使原生菜单跟踪循环立即退出。Alt 模式下，右键松开后先等待两侧 Alt 释放再弹出菜单，并有十秒上限和持续票据校验；Ctrl/Shift 不受此限制。菜单返回后向宿主补发 `WM_NULL`，按 `TrackPopupMenu` 文档完成任务切换，避免前台窗口第二次弹出菜单时出现后立即消失。
- 菜单在捕获释放后按配置生成，最终展示前再次检查实例与票据；操作复用托盘的全局事件分发和串行事务，关闭保留配置，不提供删除。
- 手势不注入内容脚本、不增加网页 IPC 能力。网页仍可能收到修饰键事件；捕获与菜单可能改变焦点，不能保证网页完全无感。钩子安装失败会提示使用托盘或管理界面；真实 WebView 的输入隔离、桌面模式和多屏行为仍须目标环境验收。

## 权限与安全边界

- 工作台与内容页面使用独立 WebView。系统权限只授予受信任的工作台，远程网页和用户导入的 HTML 均不获得文件系统、Shell 或窗口管理权限。
- 自定义 Rust 命令校验调用方、输入与目标窗口，不依赖前端隐藏按钮。内容页只能访问为其开放的最小能力集。
- 自定义资源协议 `pinpage://` 按请求所属 WebView 的页面 ID 定位站点副本，并依次完成 URL 解码、路径规范化、符号链接与目录联接检查、根目录边界确认和 MIME 类型判定；缺失或越界资源返回明确错误，不回退读取其他目录。
- 导航白名单按导航发生时的来源配置判定，来源变更后立即生效；页面记录不存在时一律拒绝。工作台自身的导航单独限制，外部链接交给默认浏览器，避免工作台 WebView 被替换为任意网页。
- 工作台使用独立 CSP；内容页权限不为加载任意网页而放宽。资源协议向内容页只返回简短错误说明和消息码，不暴露本地路径。

## 页面来源与本地副本

- **网页来源**：校验并补全 HTTP/HTTPS 地址；导航限定在该地址及页面自身来源范围内。
- **导入来源**：目录导入以所选目录为站点根，入口取根目录 HTML；单文件导入只复制入口本身；`import` 扫描阶段返回入口候选、文件数与体积，用户确认后才复制。
- 副本写入 `%APPDATA%\com.pinpage.desktop\pages\{页面 ID}\site`，配置只记录相对入口，加载不再依赖原始路径。复制跳过符号链接与目录联接，单次上限 4000 个文件或 256 MiB。
- 重新选择来源时，新内容先复制到 `pages\{页面 ID}\incoming`，再与现有 `site` 交换；中途失败会还原旧副本，页面不会指向空目录。文件仍被窗口占用时提示先关闭页面再重试。
- 更换导入来源沿用同一个页面 ID，`pinpage://{页面 ID}` 来源下的 localStorage、sessionStorage 与 IndexedDB 继续保留；改为新的网页地址后使用该地址自己的存储。
- 删除页面会清理对应站点副本。内置示例编译进二进制，按票据写成独立站点副本，与用户导入页同构，共用来源边界与导出流程。

## 页面包与数据边界

- `.pinpage` 是 ZIP，包含 `manifest.json`、`site/` 与 `data/storage.json`。
- 导出覆盖 localStorage、sessionStorage 与 IndexedDB；Cookie（含 httpOnly）、HTTP 缓存与 Service Worker 不在包内，跨机器恢复登录态并不完整。
- 采集通过注入脚本完成，数据由受控命令回传；该命令只在导出会话期间、且只接受同 ID 页面发起的调用。
- IndexedDB 逐个数据库读取，记录数据库版本、store 的 keyPath 与自增设置、索引定义和全部记录；单库最多采集 3000 条，超出后截断并在导出结果中说明。
- 记录值按类型编码，支持 Date、ArrayBuffer/TypedArray、Blob、BigInt、RegExp 与 NaN/Infinity；Map/Set 等结构化类型标记为不支持。
- 导出要求页面处于运行状态；未运行直接拒绝，数据读取超时则只打包站点副本并在结果中标注。
- 解包拒绝绝对路径、上级目录与非普通文件，清单入口必须是包内 HTML。随包数据写入 `pending-data.json`，页面首次打开时通过应用内引导页在同源空白页完成回填，再跳转入口，之后不再覆盖用户改动。

## 配置与数据模型

配置保存在 `%APPDATA%\com.pinpage.desktop\settings.json`，通过版本号、默认值和原子替换写入支持演进，窗口变化防抖保存；配置损坏时保留备份并通知用户。

| 模型 | 主要字段 |
| --- | --- |
| `AppSettings` | `schemaVersion`、`locale`、`gestureModifier`、`restoreSession`、页面配置列表、自定义预设列表 |
| `PinConfig` | `id`、名称、`source`、`enabled`、浮动/桌面模式、尺寸与位置、`scale`、置顶、边框、圆角、位置锁、大小锁、`preset`（当前匹配的预设） |
| `WindowPreset` | 自定义预设的 ID、名称与外观几何字段，位置以 `fx`/`fy` 归一化比例保存 |
| `PageSource` | URL 来源，或导入页面的相对入口 |
| `PinRuntime` | 原生窗口标签、加载状态、当前地址、可见状态、最近错误 |

持久化配置与运行态分离。配置不保存密码、网页 DOM、完整 JS 内存状态或浏览器 Cookie；网页存储由 WebView2 自身管理，导出包只读取 localStorage、sessionStorage 与 IndexedDB。刷新、销毁和重启可能丢失页面尚未保存的运行状态。

旧配置缺少或损坏的 `gestureModifier` 字段单独回退为 `alt`，不丢弃页面列表；管理命令对非法选项严格报错。全局设置持久化成功后才发布新的修饰键，失败保持旧值。

其他本地数据：

- 导入副本：`%APPDATA%\com.pinpage.desktop\pages\{页面 ID}\site`。
- 网页登录数据：由应用的 WebView2 用户数据目录管理，独立于系统浏览器。
- 应用日志与诊断信息不写入配置，避免把本地路径回显给内容页。

## 应用升级

`updates/` 模块在 Rust 中持有单个检查、下载、验签和安装任务，`commands/updates.rs` 沿用管理窗口标签与来源双重校验。只向 `main` 发出 `updates-changed` 事件，内容 WebView 不获得 updater 插件命令或应用升级能力。前端通过独立服务和业务模块展示状态，工作台关闭后任务仍可继续。

版本清单固定为本仓库 GitHub Releases 的 `latest.json`；下载地址校验仓库、具体正式版标签和 HTTPS。应用使用官方 updater 验签并强制签名绑定版本。升级偏好保存于配置目录的 `updates.json`，与页面配置的 `schemaVersion` 独立。

安装前通过操作锁和冻结标记阻止配置修改，保存会话并生成 `settings.pre-update.json`。失败时保留页面和旧进程供重试，installer 启动后由官方插件退出当前进程。未知未来配置格式保持原文件且禁止写入；安装保留原应用标识及数据目录，不承诺保存网页 JS 内存。完整流程和验收边界见[版本与升级](releases.md)。

## 多语言

- 语言偏好持久化为 `zh-CN`、`en-US` 或 `system`，默认简体中文。`system` 通过 Windows 用户首选界面语言解析，读取失败回退中文。
- Rust 在创建托盘和工作台之前解析有效语言，快照以 `resolvedLocale` 返回，前端不自行猜测系统语言。
- 错误与通知使用 `{ code, args, detail }` 消息结构，Rust 与前端读取同一份语言资源；切换语言后可见通知重新渲染，不保存已翻译句子。系统与第三方错误原文保留在 `detail`。
- 切换语言只更新 Vue I18n、页面 `lang` 和窗口标题，不刷新、销毁或重建内容 WebView；已保存的页面名称、数据和开关状态不受影响。
- 翻译资源在构建期预编译；`pnpm check:i18n` 校验中英键、参数、原生资源语法和代码中的消息键引用。

## 性能与资源

多个 WebView 可以共享浏览器基础设施，但每个页面仍有运行开销，进程数量由引擎、站点隔离和页面内容共同决定。

- 各窗口使用兼容的 WebView2 环境选项和共享数据目录，不为每个页面创建独立环境。
- 工作台按需创建、关闭后销毁；每个悬浮页只创建一个内容 WebView。
- 可见计时器和看板持续运行，不默认挂起；隐藏窗口不等于释放内存。后续若增加挂起或自动销毁，需要明确页面状态丢失与恢复行为。
- 内置计时器按目标截止时间计算剩余时间，不依赖回调次数累计秒数，覆盖后台节流与休眠恢复；第三方页面的计时准确性取决于页面自身实现。

项目提供 [`measure-memory.ps1`](../scripts/measure-memory.ps1) 测量整个应用进程组。首轮 Release 短时采样（未开始计时的内置计时器，`--tray` 启动，工作台未创建）结果如下。测试日期为 2026-11-06，环境为 Windows 10.0.26300.0、WebView2 156.0.4314.58、16 个逻辑处理器；每组独立启动，等待约 10 秒后采样 5 秒。

| 悬浮页数量 | 整组私有提交内存 | 整组进程数 |
| --- | --- | --- |
| 1 | 205.49 MiB | 7 |
| 3 | 291.34 MiB | 9 |
| 5 | 376.94 MiB | 11 |

5 页场景观察到 1 个应用进程、1 个 WebView2 浏览器主进程、5 个渲染进程和 1 个 GPU 进程。私有提交内存不等同于物理驻留内存，工作集求和包含共享页；CPU 百分比按单个逻辑核心计。样本仅用于首轮基线，不代表复杂看板或长时间运行的资源占用。首轮样本来自早期计时器版本，正式性能数据应使用优化后的版本重新采样；验收状态见[开发与构建](development.md#当前状态与验收)。

## 当前边界

- 首版发布与完整窗口能力仍以 Windows 为目标平台，同时使用 1～5 个轻量页面。macOS 已加入标准浮动窗口的能力声明与回退代码，但尚未完成交叉编译或实机验收；桌面嵌入、圆角、几何锁和原生拖动手势也未实现，不能视为完整支持。能力矩阵与验收状态见[平台支持](platforms.md)。
- 独占全屏、系统安全桌面等场景不在首版保证范围内；普通桌面窗口上方的置顶行为是首版目标。
- 新窗口链接交给默认浏览器，依赖应用内弹窗的登录流程需要按站点验证。
- 100%、150%、200% DPI、多显示器组合、连续缩放与安装卸载等场景的验收状态见[开发与构建](development.md#当前状态与验收)。
