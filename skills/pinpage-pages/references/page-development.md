# 页面制作指南

本文集中说明页面工程、内部结构、视觉与交互、数据和分发。应用连接与命令参数见[CLI 手册](cli.md)，页面能调用的原生接口及 CSP 见[宿主能力契约](host-api.md)。

## 工程目录与安装产物

普通静态工具可按以下结构组织，按实际复杂度保留需要的文件：

```text
my-tool/                    用户维护的工作目录
  site/                     安装到 PinPage 的站点根目录
    index.html              HTML 入口与语义结构
    style.css               布局、主题、透明与尺寸适配
    app.js                  交互初始化与模块装配
    modules/                可选，复杂逻辑按职责拆分
      state.js              状态校验、存储与迁移
      data.js               数据请求、解析与缓存
    assets/                 可选，随包图片、图标和字体
    data/                   可选，固定 JSON 或数据快照
      defaults.json
  README.md                 可选，给用户的使用与交付说明
```

`site/` 是推荐命名。传给 CLI 的目录应直接包含根级 HTML 入口及全部运行资源；当前目录入口必须是根级 HTML，多个候选时明确选择。普通目录导入不需要 PinPage 包清单，也不会自动进入项目根下的 `site/` 或 `dist/`。有外部资源时安装整个目录，单 HTML 安装仅复制该文件。

HTML 使用 `./style.css`、`./app.js` 等相对路径，JS 模块使用相对路径导入。脚本、样式、字体和常用图标随包提供；脚本以同源文件加载。资源类型及外部网络边界遵守宿主契约中的 CSP，避免 CDN 脚本、内联脚本、内联事件处理器和 `file://`。

随包资源和数据使用站点内相对路径，不写死页面 ID、协议主机名或绝对磁盘路径；外部数据按下文的数据来源与联网规则接入。使用 ES 模块或 `fetch` 时通过 HTTP 服务或 PinPage 预览，不能根据 `file://` 下的失败判断宿主加载能力。

Vue 等项目可在 `src/` 中开发，用 pnpm 构建为独立静态目录，例如 `dist/`，安装时选择产物目录。资源路径适合相对部署，例如 Vite 配置 `base: './'`；路由可用 hash 模式，避免依赖开发服务器回退。运行文件不引用 `/src/`、开发服务器地址、`node_modules` 或裸包名；每次修改先构建再更新原页面。交付源码与构建方法，安装目录只包含运行所需资源。

Windows 本地站点来源为 `http://pinpage.<页面 ID>`。需要安全上下文的 API 应先探测，例如 `crypto.randomUUID`，再提供适合本地工具的降级。

## 页面内部结构与基础样式

默认中文，按工具功能取舍结构。列表与看板可用“标题与工具栏、可伸缩主体、状态反馈”；简单计时器可只保留主体和状态提示。以下骨架可继续实现：

```html
<!-- 功能：组织工具标题、可滚动主体和状态反馈，加载同源脚本。 -->
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>我的工具</title>
    <link rel="stylesheet" href="./style.css" />
  </head>
  <body>
    <main class="tool-shell" aria-label="我的工具">
      <header class="tool-header">
        <h1>我的工具</h1>
        <button id="refresh" type="button">刷新</button>
      </header>
      <section class="tool-content" aria-label="主要内容" tabindex="0"></section>
      <p id="status" role="status" aria-live="polite"></p>
    </main>
    <script type="module" src="./app.js"></script>
  </body>
</html>
```

基础 CSS 将主体限定在可用高度中，隐藏滚动条，同时适配宿主背景变量：

```css
/* 功能：组织自适应布局，保留滚动，并按宿主偏好切换背景透明。 */
* {
  box-sizing: border-box;
}
html,
body {
  height: 100%;
  margin: 0;
  background: transparent;
  scrollbar-width: none;
}
.tool-shell {
  display: grid;
  grid-template-rows: auto minmax(0, 1fr) auto;
  gap: 12px;
  height: 100%;
  min-width: 0;
  padding: 16px;
  color: #253044;
  background: rgb(250 251 248 / var(--pinpage-background-opacity, 1));
}
.tool-header {
  display: flex;
  align-items: center;
  justify-content: space-between;
  gap: 12px;
}
.tool-content {
  min-width: 0;
  min-height: 0;
  overflow: auto;
  scrollbar-width: none;
}
html::-webkit-scrollbar,
body::-webkit-scrollbar,
.tool-content::-webkit-scrollbar {
  display: none;
}
```

`app.js` 负责绑定事件、渲染、恢复状态和清理资源，复杂时拆成模块。按钮服务于工具功能，原生拖窗、关闭、边框和置顶由宿主管理，不默认拦截宿主修饰键拖动和右键菜单手势。按需提供设置、空状态、加载及错误反馈，避免加载失败时留下无解释的空白页。

输入有标签，图标按钮有可访问名称，键盘焦点可见；持续变化的时间数字不每秒触发读屏播报。用户输入以文本节点渲染，不拼入 HTML。

## 布局、滚动与窗口尺寸

桌面工具通常隐藏页面和内部列表的滚动条，保留滚轮、触控板和键盘滚动。滚动容器由父布局约束高度；不要用全局 `overflow: hidden` 裁掉小窗口的设置、按钮或错误提示。独立滚动列表可设置 `tabindex="0"` 和可访问名称，并保留焦点提示；避免无意形成两层滚动。

为工具给出合适的推荐尺寸，例如：

| 形式 | 参考逻辑尺寸 | 布局建议                                     |
| ---- | ------------ | -------------------------------------------- |
| 紧凑 | `280 × 360`  | 单列突出核心数值与操作，次要内容折叠或滚动。 |
| 标准 | `420 × 480`  | 展示主要内容、辅助信息和常用操作。           |
| 宽屏 | `720 × 440`  | 切换为列表／详情或左右分栏。                 |

这些数值作为设计起点。用户可在页面设置中调整并保存页面级窗口预设；智能体按[CLI 窗口配置](cli.md#窗口配置)设置原生尺寸。首次创建可按需求设定尺寸；修改已有页时保留用户当前几何，用户要求调整时再应用选定尺寸。

布局依据实际 WebView 视区与容器的 CSS 宽高，不用 `screen.width` 推断窗口大小，也不手动乘 DPI 设置原生尺寸。优先用 Flex、Grid、`minmax(0, 1fr)`、`min-width: 0`、`min-height: 0` 和宽高断点。窄窗改为单列，宽窗按需分栏；矮窗减少装饰和间距，让次要内容滚动，保留主要操作与状态反馈。避免整页固定宽高或只靠整体缩放压缩布局。

图表和 Canvas 可用 `ResizeObserver` 观察容器，必要时用 `requestAnimationFrame` 合并更新；销毁时断开观察并取消任务。Canvas 绘制缓冲区可按 CSS 尺寸与 `devicePixelRatio` 调整。避免在尺寸回调中反复改变宿主窗口大小而形成反馈循环。

检查连续缩放、窄窗、矮窗、长文本及加载／失败状态，避免横向撑破或裁掉控件。测试已有页尺寸后恢复用户原值，或保留用户明确选定的尺寸。

## 透明背景与主题

透明效果需要原生允许背景透明和页面背景适配同时生效。宿主在顶层文档提供 `--pinpage-background-opacity`：关闭透明为 `1`，开启为 `0`；页面读取它，普通浏览器使用回退值 `1`。上面的基础样式已经配合这个变量，不要在页面中覆盖变量值。

原生偏好由页面设置的窗口外观或[CLI 窗口配置](cli.md#窗口配置)调整。透明只改变外观，应保留编辑、计时等业务状态。若当前平台或构建拒绝设置，按操作返回结果说明限制。

同时检查 `html`、`body`、根容器及铺满窗口的背景层；Vue 等项目检查 `#app` 与框架默认样式。图片、Canvas 底色和整窗卡片仍可能遮挡桌面。不要对整页设置 `opacity`，它会把文字与按钮一起变淡。

需要半透明底板时，可为局部卡片设置 `rgb(250 251 248 / 0.78)`，外层继续跟随宿主变量。提供深浅主题、文字对比和必要的边缘描边，使复杂壁纸上仍可辨认。CSS 圆角作用于网页绘制，原生圆角通过宿主边框样式设置；透明背景不会自动产生鼠标穿透。

检查普通浏览器缺省值、宿主变量 `0/1`、真实原生透明开关、深浅壁纸及窗口缩放。只有在真实桌面看到了背后内容，才报告原生透明效果已验证。

## 数据来源、联网与持久状态

先根据数据来源选择读取方式：

| 数据来源                                   | 处理方式                                                                                                      |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| 固定数据或用户提供的快照                   | 随站点提供 JSON 等资源，通过相对路径读取；修改后需要更新运行副本。                                            |
| 实时或定期更新的公开数据                   | 优先使用允许浏览器跨域读取的 HTTPS API，由页面管理刷新、缓存和失败状态。                                      |
| 本地文件列表、大小和修改时间               | 按[宿主能力契约](host-api.md)接入经逐页授权的 L1 能力。                                                       |
| 用户文件中的 JSON／CSV 等正文              | 页面提供文件输入，由用户主动选择后通过 File API 读取，或将用户提供的快照转为随包数据。L1 不提供文件正文读取。 |
| 需要私密密钥、服务端签名或不支持跨域的接口 | 确认受信任的 HTTPS 后端／代理，或改用数据快照；不在静态页嵌入服务端密钥，不默认增加常驻服务。                 |

内容页出站策略见宿主契约；CSP 允许请求仍需通过 CORS。应在实际 `http://pinpage.<页面 ID>` 来源下验证接口，开发服务器或终端请求成功不代表页面可读。`mode: 'no-cors'` 的响应不能作为可读 API 数据，客户端请求头也不能替服务端放行跨域；宿主没有通用网络代理命令。

先显示可用缓存并标注数据时间，再发起有超时与取消机制的请求。检查 HTTP 状态、字段、单位和时间格式，成功后更新界面与缓存。断网、超时、限流或上游异常时保留最后有效数据，显示失败或过期状态并允许重试；首次无缓存时显示明确空状态，不把示例或缺失数据当成实时结果。

刷新间隔符合上游更新周期与配额，限制并发并在失败后退避；查询条件变化后取消旧请求或丢弃过期结果。缓存带版本、查询条件与时间，限制大小和有效期；退出时清理轮询与请求。交付时说明数据来源、联网依赖和实际验证范围，未测量时不承诺实时性或内存数值。

持久状态使用工具专属、带版本的存储键或数据库名，例如 `pinpage-<工具名>-v1`；读取时校验类型、范围与数量，迁移旧数据，损坏时回退为可用状态。存储不可用或配额不足时保持主要操作可用并提示保存失败，高价值编辑及时保存，不只依赖 `beforeunload` 或关闭时才执行的防抖回调。

计时器保存截止时间，用当前时间计算显示，定时器只控制刷新频率，避免累计回调次数。恢复可见或从休眠返回时重新校正，仅在显示变化时更新 DOM。不默认挂起持续可见的计时器和看板；确需减少后台工作时，恢复后补算真实状态并说明对页面行为的影响。

本地页的同源存储与页面 ID 关联；localStorage 和 IndexedDB 可跨刷新与关闭重开保存。JS 变量、DOM 和未保存输入由页面负责恢复，sessionStorage 不保证关闭重开后保留。远程页面遵守站点自身同源规则，不能假设每个窗口都有独立账号。更新和关闭的具体保留规则见 CLI 手册。

## 页面包与交付

普通源码目录用于开发，构建产物用于安装运行，需要迁移分发时可使用 ZIP 格式的 `.pinpage`：

```text
my-tool.pinpage
  manifest.json             PinPage 包清单
  site/                     保留站点相对结构
    index.html
    style.css
    app.js
  data/
    storage.json            可选，由应用导出页面存储快照
```

`manifest.json` 的完整清单、默认布局与命名预设字段，以及 `data/storage.json` 的字符串存储、IndexedDB 结构、类型编码与迁移限制，统一见 [页面包文件格式](package-format.md)。无需克隆仓库即可按该参考检查实际导出文件。

可以先安装目录，通过 [CLI 命名窗口预设](cli.md#命名窗口预设)创建适合页面的布局变体，再用 [CLI 页面包导出](cli.md#页面包导出)生成 `.pinpage`。工作台也可导出。`windowPreset` 保存导出时的默认布局，`windowPresets` 保存带稳定 ID、名称和完整布局字段的有序列表，两者独立；默认布局不会自动成为命名预设。首次导入默认恢复列表并可独立选择是否应用布局；更新默认保留用户列表，显式合并或替换规则见 [CLI 页面操作](cli.md#页面操作)。CLI 默认不附带个人存储，工作台导出采集运行页数据。

只分发需要的数据，包内不携带 CLI、应用配置、页面 ID 或文件夹授权。交付源码目录、需要时的构建方法，以及用户可选择的推荐尺寸；完整运行验收流程由技能入口组织。
